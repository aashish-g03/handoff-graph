Issue routing that remembers who hands what to whom

Every time a VS Code engineer passes an issue on, Handoff Graph records it in a FalkorDB graph. When a new issue arrives, it uses that memory to route it, keep it, or ask a human, and it shows the handoff path behind every decision. Try it on a real issue.

    The same AI, with and without memory

    We replayed real VS Code triage in time order. Each issue was routed at the moment VS Code's own triage classifier first assigned it, using only what was known at that moment. Two held-out periods, each run once with a frozen design.

    VS Code's classifier is a dedicated system (classifier-deep) with per-category confidence thresholds and a hand-maintained ownership file. It's shown for scale. Handoff Graph does not beat it on a single first guess, and on the issues it routes, the two are right equally often (within 0.2 points).

      What it doesn't do

      • It doesn't beat VS Code's classifier at a single first guess: 74% vs 77% in summer, 59% vs 62% in spring. Even perfect knowledge of which issues get forwarded would reach only about 85%. Most handoffs depend on workload and absences you can't see when an issue arrives.
      • Handoff memory goes stale within weeks. The memory's best alternative named the eventual owner of 38% of bounced issues in July–August, but 13% a month later. It has to keep learning.
      • All evidence comes from one repository. It only helps where issues actually get reassigned. In Next.js, PyTorch and Rust that's 0–1%; in VS Code it's 16%.
